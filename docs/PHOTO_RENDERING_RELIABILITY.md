# 照片显示可靠性：2026-10-29 P0

适用范围：主流、照片环境光背景、连拍堆叠、同日两侧卡片和待删相册。源代码修复不等于真机验证或发布。

## 已确认的问题

1. 原生调度器把非当前卡的所有请求都当作后台任务：交互中和内存/温度压力下，优先级 1 的可见照片不能启动，低优先级背景也可能永久排队。用户看到的并非单一页面问题。之前的取消重试只处理了被取消的任务，未解决始终排队的任务。
2. 获取系统连拍成员时包含所有帧，显示、预热和恢复校验却使用默认 PhotoKit 资产查询选项；默认选项可能排除未选中的连拍成员。统一使用包含所有连拍帧的 ID 查询，仍遵守系统权限。
3. PhotoKit 可先返回低清预览；之前原生视图只有收到高清结果才触发 `onLoad`。环境背景的双缓冲等待这个事件，低清可用但高清延迟或失败时，背景可能一直是黑的。
4. 待删相册的异步元数据富化仅修改对象，没有通知 React 更新；重启后的待删视频可能仍被当成照片。现在可见页面批量接收元数据结果，及时更新媒体类型。

## 一个请求模型

- 优先级 0：当前照片；优先级 1：已经可见的相邻卡、连拍层、待删网格和环境背景；优先级 2：用户暂时看不到的推测预取。交互或压力只暂停推测预取，可见内容仍有界地前进。正常情况下为当前照片保留一个并发位置；压力下仍允许一个可见请求执行。
- 请求采用 FIFO 稳定排序；当前照片需要位置时可取消较低优先级请求，被取消的视图自行重新排队。长时间未完成的 PhotoKit 请求释放槽位并重新排队，已展示的低清图保留。
- 内存缓存分开保存最终图和临时低清预览。第一张可展示图到达即显示并触发成功回调，最终图到达时自然替换；切换背景时新层已有图才晋升。无法加载时有界重试，最终失败才显示现有错误提示。
- 窗口预热、离屏取消、视频静音和缓存上限仍在；不增加用户交互，不在本地推断照片内容，也不上传照片。
- 本地 `photo-diagnostics` 仅记录总数、错误码、iCloud 标记、队列和压力状态，不记录资产 ID、文件名或照片内容。通过更多菜单版本行长按查看。

## 测试与剩余验收

JS 行为测试覆盖可见主卡、滑动时相邻卡、连拍层、背景缓冲和待删视频元数据；Swift 调度规则在 macOS CI 中直接编译执行，原生 Swift 源码、iOS 模拟器编译及完整 JS 测试均应作为提交检查。

必须使用包含新 Swift 模块的安装包在真机复测：全本地、iCloud 优化存储及断网；主流快速滑动、左滑、前后返回；普通短时组与系统连拍未选帧；捏合后同日左右两侧；待删相册网格、照片和视频预览；后台恢复、低电量/内存压力与长时间浏览。对照旧版检查彩色背景亮度和质感。无法从模拟器或测试替身推断真机视觉、性能及 iCloud 状态。
