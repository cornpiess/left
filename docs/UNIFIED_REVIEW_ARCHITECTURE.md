# 毛球统一整理架构 · v286

基线：GitHub `cornpiess/delete_photo` 的 `master`，提交 `202f5f1ec0859b30064e6e09e86a75ed0fc91d90`。包含此前未提交的 v282 单次确认删除。

## 保留的产品选择

默认保留、左滑待删、右滑收藏、持续浏览；截图正常参与推荐、不仅凭尺寸和时间并组。没有增加强制收尾。首次引导收敛为一页价值表达，真实内容内渐进提示。所有浏览/收藏免费，每日本地日期按 100 个不同资产计新选择待删额度；同日浏览及连拍共用一条清理规则。

## 唯一状态与职责

- `reviewStore.mjs`：本地 SQLite 的已读、待删、每日额度、删除 journal；所有写操作串行；已读独立写，清理额度凭据与待删状态同一事务。PhotoKit 仍是存在性和收藏的事实源。
- `reviewStore.js`：Expo SQLite 适配；一次性事务迁移旧已读/待删/累计大小 JSON；旧浏览计数在 cleanup-policy-v1 事务中退役一次，升级后提供完整清理额度。原文件保留为迁移备份；迁移标记防止重置后重新导入；读失败不会误当空数据覆盖。此前已经淘汰的历史无法从现存数据恢复。
- `experienceCore.mjs` / `experience.js`：成功显示且稳定激活才记录已读，任何浏览不计费。另一个共享清理控制器串行处理主流/连拍/同日选择，持久化成功才执行卡片离场动画。每日以 (date, assetId) 凭据去重；撤销不返次数、当天重选不重扣。Pro 不消耗免费次数。上限统一引用 `DAILY_FREE_LIMIT=100`；文案通过 `{limit}` 插值，提升上限保留当天已用计数和去重凭据，不增加新迁移或清零。
- `candidatePager.mjs`：候选按原生分页补充，保留页边界的连续拍摄候选；原生游标不推进时返回错误，不假装完成；SQLite 按候选 ID 查询历史，4096 个近期 ID 是热缓存而不是历史上限。
- `resourceScheduler.mjs`：JS 原生元数据/IO 队列有界并发与优先级。滑动/后台限制低优先级工作。图像解码和播放不移到 JS。
- `media.js`：连接上述能力与系统相册。主流常驻元数据有界；主页面保留约 40 条近期回看窗口，移出窗口的未读组帧仍回流。待删首页用 SQL 汇总，列表每页 120 项，缓存元数据至多 600 项。

`experienceHints` / `useExperienceHints` 以已发生行为决定单条轻提示，真实首图成功后才出现，浏览后隐藏，后续按需提示左滑；旧 coach 完成状态与旧安装数据受到尊重。状态只保存在本机，不改变额度或已读记录。

## 原生 PhotoKit 模块

`modules/maoqiu-photo-preview` 是本地 Expo module，提供：

1. 共享 `PHCachingImageManager` 与请求合并/取消；预热与真实视图使用同一几何函数、64px 尺寸桶和相同 PhotoKit 参数。当前位置的后两项（优先组内下一帧）提前准备，邻近挂载视图负责回看。
2. 请求最多并发 3，低优先级最多占 2；在途请求像素预算 2400 万，预热预算 800 万。当前请求必要时取消大后台请求腾出容量；优先级提升重排未完成请求，已完成图像不因滑动失活重载。后台预览不触发 iCloud 下载，当前图像/可见待删网格才允许系统网络请求。
3. 共享已解码图像 NSCache 目标 48MiB/24 项，同一素材/尺寸复用；这是缓存目标，不是 App 总内存上限。模糊背景上限 512px，同一素材换层命中共享缓存。离屏取消并释放 UIImage。
4. 内存警告立即清缓存、取消后台请求并暂停预热 30 秒；严重发热时缓存目标降到 16MiB，请求并发降到 1。JS 接收诊断状态收缩额外播放器准备；当前显示与声音规则不改变。
5. 系统真实连拍标识；无标识时采用保守连续拍摄启发式，不做图像质量推断或强制组密度。
6. 一次 PhotoKit 删除事务和一次系统确认；旧开发运行环境有 legacy API 兼容路径，新缓存/诊断需要新二进制。

## 滑动与播放窗口

`MemoryCard` 将 active（允许播放）与 retainPlayer/videoPreload（保留或准备）分开。主流/同日最多保留当前与下一条运动资源；滚动开始同步静音，但不销毁当前实例。取消固定 250ms 停稳等待与额外 250ms 视频挂载等待；视口停稳后一个调度帧恢复播放。SDK 57 的构造器已经采用异步加载，不再沿用旧同步加载注释作为诊断依据。Live Photo 已取到的配对视频在窗口内保留，未缓存配对视频只在当前激活后取出，避免投机下载云端原文件。

PhotoKit 模式不再调用 ExpoImage 的另一套预取；旧文件兼容路径只预取短窗口，不再整组定时回填。元数据读取使用低优先级，JS 调度器为当前任务保留容量，等待中的同键任务可提升优先级。

分页追加仅对新增候选分组，已有行保持对象身份；删除/恢复仍针对有界回看窗口重建，避免引入第二套分组事实源。

## 同日浏览

`dayPager` 以选中照片为锚点，按系统游标向前/向后每页 80 项查询；首开两页，不扫描整天。待删/已返回候选跳过，异常游标不推进则报错。`mergeDayWindow` 最多保留 320 项，移出窗口的方向重新以边界查询，去重状态随窗口释放，旧照片仍可按需回看。按资产 ID 锚定画面，前插/裁剪不改变当前照片；同日数据不再全量合入主流。浏览记已读及每日 100 张待删选择规则不变。

## 本地性能诊断

原生 CADisplayLink 记录帧间隔、慢帧和最大间隔；每秒采样 resident memory，记录采样峰值，非完整峰值追踪。图像记录请求数、应用层已解码缓存命中数和平均完成耗时（不声称测得 PhotoKit 内部缓存命中率）。每 10 秒写入原有有界本地飞行记录器；后台停止采样，无照片/资产 ID、无远端遥测。用于区分掉帧、加载等待和资源压力，不代表已经完成真机性能验收。

## 删除与容量

删除前记录 journal；只提交点击时的待删 ID 快照。成功后在同一个数据库事务里更新待删记录和累计估算大小。取消保留照片，不追加失败弹窗。PhotoKit 成功但本地提交失败时保留 journal，下次只核对系统结果，不自动重删。只有完整权限和原生明确返回不存在时才确认中断任务中的删除；权限受限/查询异常不当成已删除。不确定的旧任务未核清前，不能直接再次删除。

待删总量未知大小按已有估算规则计算并显示 `≈`。累计统计命名为“已移除媒体 · 估算总大小”；它不是设备可用空间差值，不承诺进入“最近删除”就已经释放对应容量。
