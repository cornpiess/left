# 照片加载与 iCloud 故障恢复（1.0.7）

build 65 的反馈是「无法显示 · 上滑跳过」与转圈同时出现。单凭界面不能确认某张照片是否来自 iCloud；照片目录中的资产存在，也不代表本地有可解码图片。当前源码确认存在以下可导致或放大故障的路径：

- PhotoKit 请求没有队列、停滞或总时长限制，缺少最终回调会占住请求容量。
- degraded 预览回调提前清空订阅 token，布局可能重复发起请求，滑走无法取消原来的下载。
- 只有最终图片才通知 JS 已显示，已有预览时仍可能持续转圈；最终失败又覆盖预览。
- 失败状态缺少手动重试，转圈条件没有排除最终失败；背景层还可能持续重新挂载重试。
- 视频错误和首帧超时调用翻页，弱网时会跳过未观看内容。

## 统一加载策略

所有原生 PhotoKit 表面（主信息流、连拍、同日、待删网格/预览、背景、视频封面）共享 PhotoResources。

| 环节 | 策略 |
| --- | --- |
| 本地 | 先请求屏幕尺寸图片，不等待原图导出；2.5 秒无最终结果则结束本地探测。缓存预览立即显示。 |
| 云端 | 当前/相邻照片及显式允许联网的可见网格才可升级到 iCloud；背景不能主动下载。 |
| 并发 | 总请求最多 3、后台最多占 2、云端最多 1；当前照片需要云端时取消相邻照片的云端请求。本地解码继续使用其他容量。 |
| 等待 | 排队最多 8 秒；云端 12 秒没有进度增长或单次总时长达 30 秒即取消。重复相同进度不能续期。 |
| 重试 | 当前照片的瞬时故障最多自动重试 1 次；调度取消最多重试 2 次。布局重排不会自动重试失败请求。 |
| 退避 | 同一照片近期失败抑制后台下载；30 秒内 3 张照片失败，暂停新的后台云端升级 20 秒。当前照片仍可尝试。 |
| 网络 | 第一次需要云端时才开始被动观察网络路径，无 HTTP 探测。离线取消云端任务；恢复连接只唤醒当前未完成照片，恢复事件至少间隔 3 秒。切回前台和相邻卡变为当前卡也可重新尝试。 |
| 取消 | 退订最后一个订阅者时取消实际 PHImageRequestID。任务和阶段身份先失效，迟到回调、旧定时器不能完成新请求。 |
| 预览 | degraded 图片真正写入视图后就通知已显示；下载订阅继续保留。升级失败保留已有图，不显示错误层或转圈。 |
| 失败 | 无图才显示错误；区分离线、照片移除/无权访问、临时失败。提供重试按钮及继续上滑提示，六种语言共用布局。 |

PHImageRequestOptions 的请求尺寸决定显示资源；这里不主动批量下载原图，也不把蜂窝网络一概判断为弱网。系统可自行决定从 iCloud 获取哪些数据。30 秒是每次云端尝试的上限，不是包括排队、本地探测、重试在内的整张照片总等待时间；用户始终可以滑走。

## 状态与整理记录

- 只有实际显示的照片（包括可见的预览）或实际播放出首帧的视频，才进入现有 exposure 流程。失败、重试、上滑继续均不生成已看记录。
- 恢复显示后清除本次会话的未解决故障计数，避免末尾错误页残留。
- 视频失败释放播放器，留在当前卡，点击重试创建新播放器。视频首帧等待限 15 秒；此处不宣称播放器提供 PhotoKit 图片管线的逐字节进度或原生下载调度能力。
- Live Photo 静态部分使用统一图片管线；动态部分保留原有 expo-video 链路。本文的原生图片截止时间不适用于视频播放和 Live Photo 动态资源。
- 旧二进制文件渲染分支保留降级链，补上最后一级 watchdog；它无法获得本次新增的原生取消能力。必须发布新 iOS 二进制。

## 验证与可观测性

本地已通过：322 项 Node 测试（含界面真实事件驱动的失败/重试/预览保留/迟到回调/视频重试/未看记录检查）、不可变绑定和促销配置检查、`expo export --platform ios`、`git diff --check`。

原生 XCTest 新增 6 项，使用生产 PhotoLoadClock / PhotoRetryBudget，覆盖本地截止、停滞、重复/倒退/非法进度、硬截止、自动重试和取消预算。iOS 检查工作流已覆盖 PR，执行这些测试与原有像素回归，并无签名编译完整 App。运行结果以 PR 检查为准；本地 Linux 的 JS 导出不能证明 Swift 编译成功。

飞行记录器新增 cloud / timeout / preview / offline 计数；原生失败记录包括 queue-timeout、cloud-timeout、offline、deferred、asset-missing 等原因，不记录照片 ID、路径或图片内容。网络路径可用不代表 Apple 服务可用，服务故障依靠实际请求结果和超时判断。

发布前真机验收：优化储存的 iCloud 大图库、飞行模式、很慢但持续有进度的网络、网络连通但 iCloud 不响应、下载时切下一张/连拍/同日/待删、前后台切换、网络恢复、有限照片权限、内存压力。必须确认本地图可继续浏览、已显示预览保留、失败照片未被计入已看、重试恢复且没有持续请求增长。
