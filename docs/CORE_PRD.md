# 毛球核心 PRD：产品原则与交互宪法

> 文档版本：4.2
> 更新日期：2026-10-28  
> 适用范围：产品设计、交互、视觉、媒体播放、推荐/分页、会员配额、数据状态及相关测试

## 0. 文档权威与使用方式

本文定义毛球长期稳定的**目标行为**，是后续产品设计和 AI 开发的产品单一事实源。

- 需求冲突时，优先级为：用户本轮明确要求 → 本 PRD → 专项技术决策/测试 → `AGENTS.md` 历史记录 → 当前代码行为。
- 当前代码只代表“现在如何实现”，不自动代表“产品应该如此”。代码与本文冲突时，应标记为产品缺口。
- 版本号、实现细节、临时故障和发布状态写入 `AGENTS.md` 或工作日志，不沉淀到本文。
- 修改本文所列 P0 不变量，必须由用户明确决定；不得在重构、性能优化或视觉调整中顺带改变。

## 1. 产品定义

### 1.1 一句话定位

毛球是一款**像刷短视频一样轻松、像整理实物一样可信的本地相册清理工具**：用户每次只面对一个清晰的媒体决策，通过稳定手势快速浏览、收藏或暂存删除。

### 1.2 核心任务

用户无需进入复杂的文件管理界面，即可连续完成：

1. 看清一张照片、实况照片、视频或一组连拍。
2. 通过固定方向表达保留、收藏或清理意图。
3. 随时回看、撤销和最终确认删除。
4. 在不重复消费旧内容的前提下持续推进相册整理进度。

### 1.3 北极星体验

**一屏一张、一划一意图、音画唯一、删除可悔、看过不再推。**

产品成功首先表现为：用户无需思考操作含义，不会听到错误媒体的声音，不会误删内容，也不会被系统反复推送已经处理过的照片。

## 2. 优先级定义

- **P0 产品不变量**：安全、信任和基础心智。任何版本都必须成立。
- **P1 核心体验**：直接影响效率与可理解性，应作为功能验收门槛。
- **P2 品牌表达**：在不破坏 P0/P1 的前提下塑造毛球的个性。

发生冲突时，始终按照 **安全与隐私 > 意图正确 > 音画正确 > 内容连续 > 视觉表现 > 装饰效果** 收敛方案。

## 3. 十条核心指导思想

### 3.1 一张卡片就是一个决策对象（P0）

当前屏幕只能有一个明确的主媒体和一个明确的操作对象。信息、手势反馈、声音、收藏状态、删除状态和分享目标必须全部指向同一 `assetId`。

验收：任何过渡帧都不能出现“A 的画面、B 的声音、C 的信息或操作结果”。

### 3.2 方向就是意图（P0）

方向语义全局稳定：**上下浏览、左滑清理、右滑收藏**。同一个方向不得因媒体类型、页面位置或会员状态改变含义。

验收：用户在主信息流任意卡片上执行相同方向手势，结果语义一致；未越过提交阈值时安全回弹且不修改数据。

### 3.3 声音只有一个主人（P0）

任意时刻最多一个播放器允许发声，这个播放器必须属于当前已稳定激活的媒体。开始切换的瞬间先静音和暂停旧媒体，再处理动画、索引和新播放器。

验收：快速上下滑、左右滑、捏合、旋转屏幕、打开弹层、进入后台和连续切换视频/实况照片时，均无残留音轨、重叠音轨或错位音轨。

### 3.4 看过不再推（P0）

推荐流只提供用户尚未看过的媒体。历史耗尽时呈现明确完成态，不通过循环、洗牌或兜底重新推荐已浏览内容。

验收：同一持久化浏览历史下，自动分页、重启和跨日配额刷新不会把已浏览 `assetId` 重新加入新推荐候选。用户回看及恢复上次稳定节点属于既有浏览上下文，可以展示已读照片；不重新推荐、不重复扣额，也不重复累计连拍间隔。

### 3.5 删除必须可悔（P0）

左滑只把媒体移入 App 内“毛球”收集箱；真正删除到 iOS“最近删除”必须在收集箱内由用户再次明确触发，并遵循系统确认流程。一次清理只提交一次系统删除事务，系统弹窗是唯一确认；App 不叠加确认，不因分批请求反复打断用户。等待时显示真实忙碌状态，不伪造百分比；取消或失败保留待删项。删除只传标识，不为删除加载媒体。恢复操作必须保留原媒体，不制造副本。

验收：主信息流不存在一步永久删除；误触左滑后至少有可见撤回或收集箱恢复路径。

### 3.6 反馈先于等待（P1）

用户越过操作阈值后，界面必须立即通过方向色、位移、图标/文字、触觉或状态变化确认意图；耗时的数据写入在后续完成。反馈不能依赖网络或媒体重新解码。

验收：离线和低性能设备上，手势仍跟手；成功、失败、收藏状态和删除去向均可感知。

### 3.7 内容优先于界面（P1）

照片和视频是绝对视觉主体。界面只解释内容和承载操作，不遮挡关键区域，不拉伸媒体，不用装饰争夺注意力。媒体按原始宽高比完整呈现；若必须裁切，需由具体场景明确授权。

验收：横竖构图均无形变；加载切换无空白闪烁、非预期黑闪或旧帧串卡。

### 3.8 连续性优先于炫技（P1）

预加载只服务于下一步的无缝体验，不能抢占当前媒体的声音、内存或渲染所有权。动效用于解释对象从哪里来、到哪里去，不能延迟意图生效。

验收：当前卡优先获得解码和播放资源；预加载播放器始终静音且无可见输出；低内存时可降级装饰，不能降级正确性。

### 3.9 MD3 是系统，不是皮肤（P1）

颜色、排版、形状、间距、层级、组件状态和运动统一使用设计令牌与共享组件。Liquid Glass 和“毛球”品牌元素可以作为视觉表达，但必须服从 Material Design 3 的层级、状态和可访问性原则，并尊重 iOS 平台习惯。

验收：新界面不引入孤立颜色、字号、圆角、阴影或动画曲线；同类控件在不同页面有一致的 enabled、pressed、disabled、selected、loading 和 error 表达。

### 3.10 隐私默认成立（P0）

相册分析、浏览历史、收藏/收集箱状态和媒体处理默认在设备本地完成。只申请完成当前功能所需权限；任何媒体上传、远端分析或新增数据收集都必须获得用户明确授权并同步更新隐私说明。

验收：断网不影响核心浏览与整理；未经授权，不向第三方发送媒体内容或可还原个人相册的信息。

## 4. 主信息流交互合同

### 4.1 通用手势

| 输入 | 固定语义 | 提交结果 | 未提交/取消 |
| --- | --- | --- | --- |
| 上滑 | 前进到下一条未浏览内容 | 下一卡稳定激活后记为已浏览，并成为唯一 active | 回到当前卡 |
| 下滑 | 返回近期浏览窗口内的上一条 | 只回看，不产生新推荐、不重复扣配额 | 回到当前卡 |
| 左滑 | 移入毛球 | 当前决策对象进入 App 收集箱，再前进 | 卡片安全回弹，数据不变 |
| 右滑 | 收藏/取消收藏 | 切换当前对象收藏状态，停留当前卡 | 卡片安全回弹，数据不变 |
| 双指向内捏合 | 进入“回到那一天” | 以当前媒体为锚点浏览同日内容 | 阈值不足则回到当前卡 |
| 双指向外捏合 | 放大当前照片/实况/连拍帧 | 1x–4x 缩放并允许平移 | 回到 1x 后恢复信息流手势 |

补充规则：

- 手势从触点落下开始仲裁，一次触摸序列只能提交一种意图。
- 纵向滚动与横向决策必须有方向锁；对角线不满足横向优势时归纵向浏览。
- 缩放状态独占触摸，期间禁用上下分页和左右决策，避免误删。
- 横屏为当前媒体预览态；旋转、进出预览和恢复竖屏不得改变当前 `assetId` 或重复计数。
- 手势阈值是实现参数，可通过真机调优；方向语义、取消安全和数据结果不可改变。

### 4.2 按媒体类型的行为矩阵

| 类型 | 单击 | 长按 | 向外捏合 | 自动行为 |
| --- | --- | --- | --- | --- |
| 视频 | 暂停/恢复 | 按住 2 倍速，松手恢复 | 不缩放 | active 且页面稳定后有声循环 |
| 单张实况 | 无 | 无 | 1x–4x；放大时显示可控静态帧 | active 时播放，服从全局声音唯一性 |
| 静态照片 | 无 | 无 | 1x–4x并可平移 | 可使用克制的 Ken Burns 微动效 |
| 连拍组 | 切换下一帧 | 按当前帧类型执行 | 缩放当前帧 | 手动切帧，不自动推进整组 |

所有类型共享：上/下浏览、左滑移入毛球、右滑切换收藏、向内捏合进入同日浏览。

### 4.3 连拍原则

- 连拍组是一个浏览单元，但组内每一帧是独立决策对象。
- 切帧必须保持卡片位置、尺寸和背景连续，不出现黑帧或错误帧。
- 左滑只处理当前帧；若组内仍有帧，下一帧自然成为当前对象；组耗尽后才进入下一条。
- 收藏、分享、信息和删除始终作用于当前帧，不得默认作用于整组。
- 系统连拍信息优先；无系统标识时仅按保守的时间和尺寸规则组织“连续拍摄组”，不宣称内容相似。候选充足时，新会话先呈现 2 张单卡，后续两组之间安排 3–5 张新单卡；组内翻帧、预取、回看和重启不重复累计。所有候选来源经过同一调度，分页不重置。没有合格组时不凑数、不阻塞；只剩组时可把尚未展示的部分组改为逐张呈现，关系保留、成员不丢失，已打开的组不拆。截图参与普通推荐，但不能仅按尺寸/时间并入组。

### 4.4 “回到那一天”原则

- 这是用户主动进入的上下文浏览，不属于自动推荐，因此可以展示同日已浏览媒体。
- 入口锚点固定为触发捏合的媒体；退出后返回原主信息流位置和原决策对象。
- 进入、切换和退出均执行声音所有权交接；只有当前居中媒体可以发声。
- 同日浏览中的删除仍遵循“先进入毛球、可恢复”的两阶段删除规则。

### 4.5 浏览连续性

- 杀掉 App、回到前台或临时界面返回后，优先恢复最后已持久化的稳定照片；连拍恢复同一帧，同日浏览保留当前帧和主流返回锚点。
- 当前身份、附近已承诺顺序和出现节奏使用同一份本地快照；以 assetId 定位，不持久化像素滚动位置。
- 停稳时保存，后台刷新仅作补充。加载失败不记已读；手势中断恢复此前稳定节点。
- 已待删或无权访问的节点跳过，按原顺序优先选择后继；iCloud 暂不可用保留锚点，不当作删除。
- 不增加继续按钮，不重新弹出购买、分享或设置界面；新候选在后台补充，不插入当前卡片之前。

## 5. 音频与播放状态机

### 5.1 唯一所有权

系统维护一个全局 active player 所有权。仅同时满足以下条件的播放器可以解除静音并播放：

1. App 位于前台且当前页面获得焦点。
2. 卡片是当前确定性 active 卡片。
3. 页面没有滚动、横滑、捏合、删除动画、弹层遮挡或模式切换。
4. 播放源已就绪，播放器身份与当前 `assetId` 一致。

其余播放器必须同时处于 `muted = true` 与 `paused` 状态；下一卡预加载器只能静音预缓冲，不得拥有可见播放视图或音频会话。

### 5.2 先静音、后切换

以下事件发生时，在同一事件入口立即静音并暂停当前及已注册播放器，不能等待 React 状态提交、滚动停止或动画完成：

- 任意触摸拖动开始，包括尚未判定方向的拖动；
- 主信息流上下切卡或连拍切帧；
- 左滑删除、右滑收藏；
- 双指捏合、进入/退出同日浏览；
- 打开收集箱、菜单、付费墙或其他遮挡主内容的弹层；
- 横竖屏切换、页面失焦、App 进入后台、组件卸载或播放报错。

新媒体只能在索引稳定、身份核对通过且视图 ready 后恢复声音。恢复顺序为：确认所有权 → 解除当前播放器静音 → 播放。

### 5.3 播放容错

- 加载态必须与当前媒体绑定，旧媒体的 ready/error 事件不得更新新卡状态。
- 视频无法加载时显示可理解的局部失败态，保留继续上滑能力；不得用错误视频或纯黑无限等待代替。
- 播放失败、卡片离开 active 或 App 失焦后，播放器不得自动抢回声音所有权。

## 6. 内容分发、浏览历史与配额

### 6.1 “已浏览”的定义

媒体必须成功显示且成为稳定 active 决策对象后，才记录该帧 `assetId`。照片以正常图像显示成功为准，视频以首帧实际显示为准；预加载、低清占位、快速划过、加载失败都不记已读、不扣配额。完整记录存于本地 SQLite；内存热缓存可以有界，但不得删除持久化历史。

### 6.2 不重复分发

自动推荐候选必须同时满足：

- 不在持久化 `viewedHistory`；
- 不在当前会话已服务集合；
- 不在毛球收集箱或系统已删除集合；
- 当前权限允许访问；
- 能形成可识别且可交互的媒体对象。

未浏览内容耗尽时进入完成态，并提供明确的下一步，例如查看毛球、调整相册权限或由用户主动重置浏览历史。系统不得自动执行以下行为：

- 回退到已浏览候选；
- 清空会话集合后循环；
- 因跨日、重启、升级、会员状态变化或配额恢复而清空浏览历史；
- 用文件名、缓存 URI 或数组位置替代稳定 `assetId` 去重。

### 6.3 允许再次出现的边界

以下不是“重新推荐”：

- 用户在当前信息流向下滑回已经加载的上一张；
- 用户主动进入同日浏览、毛球、收藏或其他明确的历史/集合页面；
- 用户明确执行“重置浏览历史”，并理解重置后旧内容会重新进入候选池。

恢复出毛球的媒体仍保持“已浏览”状态，不自动回流到推荐。

### 6.4 配额与历史解耦

- 浏览、同日回顾、收藏不设数量限制；成功展示只写已读，不消耗清理额度。
- 免费用户每天可新选 100 张媒体加入待删相册；主流、连续拍摄组各帧与同日浏览共用规则，以稳定资产 ID 去重。
- 待删状态和额度凭据在同一个 SQLite 事务提交；成功后才移走卡片，失败时保留原位且不扣额度。
- 当天撤销或恢复后重新选择同一媒体，不重复扣额度；恢复不返还已消费次数。跨日按本地日期刷新新选择额度，既有待删项不重新收费。
- 超额仅拦截新的待删选择：照片回弹原位，直接打开统一购买组件。关闭/取消/购买成功后保留浏览位置，不自动执行刚才未完成的删除意图。
- 恢复、撤销及已选媒体的系统删除始终免费；不可用付费限制阻止完成已选清理。
- 每日额度刷新不清空浏览历史；重置历史也不重置额度或当天去重凭据。
- PRO 解除清理数量限制；隐私、安全、声音和删除恢复规则与免费版一致。
- 旧版本的浏览额度不换算为新清理额度；升级一次性退役旧计数，保留历史、待删、统计及会员权益。

### 6.5 从理解价值到付费的一条路径

- 首次打开只有一个价值页面：“像刷短视频一样，轻松清理相册。”本地示例自动演示一次上下浏览、左滑整理与待删检查；触摸即接管，可撤回。无操作考试；开始按钮始终可用。更多手势按需展开，菜单重看复用同一组件。示例与真实资产、历史、配额和会员完全隔离。
- 点击“看看我的相册”请求系统权限；完整或有限权限授权后直接进入真实照片。拒绝后可打开设置，返回前台会重新检查，不再增加一轮教学。
- 所有手势教学在前置引导完成；真实信息流不自动出现教学浮层、手势 tips 或因教学抬高照片。保留真实操作反馈、撤回和错误提示。不要求必须删除、不强制收尾。
- 首次及后续选择都明确“加入待删相册，尚未删除”，并提供撤销。系统删除仍只有系统确认。
- 菜单与超额使用同一个购买组件，直接选择原有包年或终身方案进入 StoreKit；不设置额外的限额落地页。
- 付费价值是无限清理，不把隐私/撤销当付费权益，不承诺未实现的未来功能；明确免费范围、每日刷新、续订规则与恢复购买。
- 体验指标围绕首张真实照片、首次待删选择、成功完成清理和付费需求。当前仅复用本地有界诊断记录保存耗时/入口/成功事件，不上传照片或行为遥测；这些记录不等于已证明转化率提升。

## 7. 收藏、毛球与数据一致性

### 7.1 收藏

- 右滑只切换当前 `assetId` 的 iOS 收藏状态，不自动前进。
- 操作必须幂等：快速重复手势或异步回调乱序不能造成 UI 与系统收藏状态相反。
- 收藏不等于“未浏览”；收藏后的媒体仍从自动推荐池排除。

### 7.2 毛球

- 左滑后立即从主推荐候选和当前可见集合移除，并加入毛球顶部。
- 撤回/恢复必须恢复同一 `assetId`，同时移出毛球；其浏览历史保持不变。
- 永久清理是独立的高风险操作，需要清晰展示对象数量和预计空间，并接受 iOS 系统确认。
- 每次清理只发起一个系统删除事务，不在 App 内叠加确认、不自动拆批重试。删除前持久化操作记录，成功后原子提交待删状态与媒体估算大小。中断后只核对系统结果，不自动重删；取消不弹失败提示。

### 7.3 状态一致性

任何操作完成后，卡片、信息面板、分享对象、收藏状态、毛球计数、空间统计和持久化数据必须基于同一媒体身份。异步结果返回时先核对 `assetId` 和操作版本，再更新界面。

## 8. 视觉与 MD3 设计原则

### 8.1 设计语言

毛球采用 **MD3 结构与状态 + iOS 平台行为 + Liquid Glass 品牌表面**：

- MD3 决定信息层级、组件角色、状态、令牌、间距和运动语义。
- iOS 决定安全区、系统权限、系统确认、返回习惯、辅助功能和原生媒体行为。
- Liquid Glass、猫咪与毛球元素负责品牌识别，不改变核心控件含义。

### 8.2 令牌化

- 颜色、字号、字重、行高、圆角、描边、阴影、透明度、间距和运动曲线必须来自共享令牌或共享组件。
- 间距以现有 4/8 基础网格组织，优先使用 `4、8、16、24、32`。
- 同一层级只保留一个最高强调动作；危险操作使用稳定的危险语义色和明确文字。
- 新样式先判断是否能扩展现有 token/component；不能时再新增语义令牌，不写页面私有“魔法值”。

### 8.3 状态可见

- 所有交互控件至少具备 enabled、pressed、disabled；异步控件还应具备 loading、success/error 或等价反馈。
- 重要状态不能只靠颜色区分，至少结合形状、图标、文字、位置、动效或触觉中的另一种信号。
- 自定义按钮必须有即时按压态；手势提交前后必须有连续的视觉映射。

### 8.4 可触达与可读

- iPhone 常用控件点击热区目标为 **48×48 pt**，任何常用控件不得低于 iOS 推荐的 **44×44 pt**；视觉图标可更小，热区不可缩小。
- 正文和控件文字应支持动态字体或可靠的弹性布局；翻译变长时允许换行，不裁断关键操作。
- 普通小字号文本对背景对比度目标不低于 4.5:1，大号或粗体文本不低于 3:1。
- 每个图标按钮、媒体状态和危险操作提供准确的 VoiceOver 标签、角色、状态和值。
- 核心操作除手势外应在适当页面提供可访问替代路径；至少确保毛球内可以按钮恢复和永久清理。

### 8.5 运动

- 进入/回弹使用 MD3 强调减速语义，离场/提交使用强调加速语义；运动解释状态变化，不做无意义等待。
- 动画主要使用 transform 与 opacity，保持手势跟手；数据状态在提交点生效，不等待装饰动画。
- 删除、收藏和分页的轨迹必须保持对象连续性，用户能看懂对象去了哪里。
- 尊重“减少动态效果”；启用后缩短或移除 Ken Burns、呼吸和弹性装饰，同时保留状态反馈。

### 8.6 媒体舞台

- 主媒体保持原始宽高比，默认完整显示，不拉伸。
- 控件避开刘海、Dynamic Island、Home Indicator 和视频进度条的触摸区域。
- 背景可以使用媒体取色、模糊或有意的纯黑沉浸场景；加载失败和媒体换帧不得出现无意的纯黑闪烁。
- 信息与操作覆盖层必须保持可读，不能因背景明暗变化丢失对比度。

## 9. 性能、离线与降级

- 候选按系统分页获取，不全库扫描/驻留；当前流保留近期回看窗口，移出窗口的未读组帧仍回流候选。
- 首页待删数量/容量直接从数据库汇总；待删列表每页 120 项，图像与视频封面按显示尺寸请求。
- PhotoKit 使用共享缓存、匹配显示尺寸的短窗口预热；图像请求最多并发 3，后台预览最多占 2，并按像素预算限制解码；离屏取消并释放图像。内存/热压力下收缩预热和装饰资源。
- 视频资源准备与播放激活分离；滑动立即静音，但窗口内保留资源，不叠加固定停稳/播放器创建等待。
- 同日浏览按锚点双向分页、按资产 ID 保持位置，常驻窗口有界；分页追加不重组已有列表。
- 原图用于明确需要原文件的操作；当前照片的常规展示、背景和网格不为此导出原文件。
- 容量未知时标“约”；累计统计是已移除媒体的估算大小，不声称测得设备可用空间增量。

- 首张可交互优先于完整目录扫描；分页和连拍识别在后台渐进完成。
- 当前卡、相邻卡和下一视频预加载有清晰资源优先级；远端/iCloud 等待不得阻塞本地可用内容。
- 核心整理流程离线可用。iCloud-only 内容应提供真实准备状态，不伪装为空相册或加载成功。
- 资源不足时按顺序降级：装饰动画 → 背景效果 → 邻近预加载；手势、身份、声音、删除安全和不重复分发不得降级。
- 错误状态说明发生了什么，并保留安全的继续路径；不得自动跳过让用户无法判断的媒体。

## 10. 国际化与文案

- 所有用户可见文案进入统一 i18n 资源，不在组件中硬编码中文或英文。
- 六种现有语言的功能语义必须一致；翻译不能改变危险程度、订阅含义、收藏状态或删除去向。
- 文案优先说明结果，例如“移入毛球”“从毛球恢复”“扔到 iOS 最近删除”，避免含糊的“确定”“处理”。
- 空状态区分真实原因：内容已看完、权限受限、iCloud 准备中、加载失败、毛球为空、配额耗尽。

## 11. AI 设计与开发决策协议

任何会影响信息流、手势、播放、声音、浏览历史、配额、收藏、删除、视觉组件或辅助功能的改动，执行前必须：

1. 指出受影响的 PRD 条款和产品不变量。
2. 画清对象身份与状态转换，尤其是 active、viewed、favorite、trash、player owner。
3. 先处理取消、快速连续操作、异步乱序、App 失焦、媒体失败等边界，再选择动画和实现方式。
4. 将产品规则写成自动化测试或可重复真机验收步骤。
5. 核对所有媒体类型、六种语言、普通/PRO、前台/后台和有声/无声路径。
6. 发现代码与本文冲突时明确报告，不得以“保持现有行为”为理由静默保留冲突。

完成标准：实现不仅在单次正常操作下成立，也能通过第 12 节回归门禁。

## 12. 核心回归门禁

每次发布前至少验证：

### 12.1 手势与身份

- 连续快速上滑 20 次：无重复卡、错卡、跳卡和配额重复扣减。
- 上下往返浏览：下滑只回看，上滑回到既有位置不再次计费或重新推荐。
- 对角线、短距离左右拖动和缩放后误触：均不误删、不误收藏。
- 照片、实况、视频、连拍分别通过完整行为矩阵。

### 12.2 声音

- 视频 → 视频、视频 → 实况、实况 → 视频快速切换：全程最多一条音轨。
- 手指刚开始拖动、打开任意弹层、进入后台和旋转屏幕：旧声音立即停止。
- 预加载、错误重试和旧播放器回调不会抢回声音。

### 12.3 不重复与配额

- 重启 App、跨日、刷新免费配额、升级缓存后，已浏览内容仍不进入自动推荐。
- 内容耗尽显示完成态，不循环旧内容。
- 重置浏览历史前有明确用户动作；重置配额不改变浏览历史。

- 第 100 张选择成功，第 101 张新资产回弹；已计数资产当天恢复重选不重复收费。同日入口和连拍不能绕过规则。
- 超额后仍可浏览、收藏、恢复并免费删除已选媒体；取消购买不移走当前照片。

### 12.4 删除安全

- 左滑后对象只进入毛球，可撤回、可恢复。
- 永久清理必须从毛球发起并显示准确结果；取消系统确认后数据不丢失。
- 连拍删除只作用于当前帧，收藏/分享/信息对象始终一致。

### 12.5 视觉与可访问性

- 小屏、刘海屏、横屏、动态字体和六种语言下无关键控件遮挡或文案截断。
- 常用点击热区不小于 44×44 pt，目标为 48×48 pt；自定义控件有 pressed 状态和 VoiceOver 标签。
- 开启减少动态效果后仍能理解所有状态变化。

## 13. 实现与验证状态（2026-10-27）

统一状态、成功展示记已读、原子额度、完整历史、候选分页、待删汇总/分页、单事务删除及恢复日志见 `docs/UNIFIED_REVIEW_ARCHITECTURE.md`。原生 PhotoKit 预览需要新二进制安装；JavaScript 导出与自动链接检查不等于 Xcode 编译或真机性能验收。首次体验、清理额度与购买路径按第 6.4–6.5 节统一；持续浏览保留。
